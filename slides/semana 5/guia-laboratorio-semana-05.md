## 1. Contexto da missão

A Task API criada nas semanas 3 e 4 funciona, mas guarda as tarefas em uma lista na memória da aplicação. Ao reiniciar o servidor, todo o trabalho dos usuários desaparece.

Imagine uma empresa que anota todos os pedidos de clientes em uma lousa e a apaga ao fim do expediente. Sua missão é instalar o **arquivo físico**: um banco de dados relacional, acessado por meio do Spring Data JPA.

Você **não** reescreverá a lógica de negócio. A arquitetura em camadas permite trocar a forma de armazenamento alterando apenas a camada de dados.

### Objetivos de aprendizagem

Ao final, você será capaz de:

1. configurar o Spring Data JPA com o banco H2;
2. mapear uma classe Java como entidade;
3. criar um repositório com `JpaRepository`;
4. adaptar o `Service` para usar o novo repositório;
5. ler o SQL gerado pelo Hibernate;
6. comprovar que os dados sobrevivem à reinicialização.

### Níveis da missão

| Nível | Descrição | Obrigatório |
|---|---|---|
| Bronze | Passos 1 a 4: entidade e repositório funcionando | Sim |
| Prata | Passos 5 e 6: migração completa e SQL analisado | Sim |
| Ouro | Passo 7: persistência em arquivo e desafios | Não |

## 3. Passo 1: adicionar as dependências

Abra o `pom.xml` e verifique se as dependências abaixo estão presentes. Se não estiverem, adicione-as (ou gere um novo projeto em **start.spring.io** selecionando *Spring Data JPA* e *H2 Database*).

## 5. Passo 3: transformar `Task` em entidade

Abra a classe `Task` e aplique as anotações de `jakarta.persistence`:

```java
package br.edu.ifrn.tarefas.model;

import jakarta.persistence.*;
import lombok.AllArgsConstructor;
import lombok.Getter;
import lombok.NoArgsConstructor;
import lombok.Setter;

@Entity
@Table(name = "tarefas")
@Getter
@Setter
@NoArgsConstructor
@AllArgsConstructor
public class Task {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, length = 100)
    private String titulo;

    private String descricao;

    private boolean concluida;

    @Enumerated(EnumType.STRING)
    private Priority prioridade;
}
```

> Ajuste o nome do pacote ao do seu projeto.

**Pontos de atenção:**

- Os imports devem ser de `jakarta.persistence`, nunca `javax.persistence`.
- Não utilize `@Data` em entidades.
- O `id` deve ser `Long` (objeto), e não `long` (primitivo).
- Se a sua `Task` tinha lógica de geração de `id` (contador manual), **remova-a**: o banco passa a ser o responsável.

### Atividade de verificação (Bronze)

Inicie a aplicação e localize no console o comando abaixo (a ordem das colunas pode variar):

```sql
create table tarefas (
    concluida boolean not null,
    id bigint generated by default as identity,
    titulo varchar(100) not null,
    descricao varchar(255),
    prioridade varchar(255),
    primary key (id)
)
```

Registre uma captura de tela deste trecho para a entrega.

## 6. Passo 4: criar o repositório JPA

Se existir um `TaskRepository` como **classe** com uma `List<Task>` interna, **substitua-o** por uma interface:

```java
package br.edu.ifrn.tarefas.repository;

import br.edu.ifrn.tarefas.model.Task;
import org.springframework.data.jpa.repository.JpaRepository;

public interface TaskRepository extends JpaRepository<Task, Long> {
}
```

Observe: **não há implementação**. O Spring Data a gera na inicialização.

Recomendação: antes de apagar o código antigo, salve-o em um arquivo de apoio ou faça um commit, para poder comparar depois.

**Checkpoint (Bronze):** a aplicação inicia sem erros de compilação em `TaskService`? Provavelmente não, pois o Service ainda chama métodos do repositório antigo. Siga para o Passo 5.

## 7. Passo 5: adaptar o Service

Compare os métodos do repositório antigo com os do `JpaRepository`:

| Operação | Repositório em memória (exemplo) | JpaRepository |
|---|---|---|
| Listar todas | `listarTodas()` | `findAll()` |
| Buscar por id | `buscarPorId(id)` | `findById(id)` |
| Salvar ou atualizar | `salvar(task)` | `save(task)` |
| Remover | `remover(id)` | `deleteById(id)` |
| Verificar existência | percorrer a lista | `existsById(id)` |

Adapte o `TaskService`:

```java
@Service
@RequiredArgsConstructor
public class TaskService {

    private final TaskRepository repository;

    public List<Task> listar() {
        return repository.findAll();
    }

    public Task buscar(Long id) {
        return repository.findById(id)
                .orElseThrow(() -> new NoSuchElementException("Tarefa não encontrada: " + id));
    }

    public Task criar(TaskRequest dto) {
        Task task = new Task();
        task.setTitulo(dto.titulo());
        task.setDescricao(dto.descricao());
        // mantenha aqui a lógica de prioridade criada na Semana 4 (Strategy)
        return repository.save(task);
    }

    public Task atualizar(Long id, TaskRequest dto) {
        Task task = buscar(id);
        task.setTitulo(dto.titulo());
        task.setDescricao(dto.descricao());
        return repository.save(task);
    }

    public void remover(Long id) {
        if (!repository.existsById(id)) {
            throw new NoSuchElementException("Tarefa não encontrada: " + id);
        }
        repository.deleteById(id);
    }
}
```

> **Importante:** preserve o uso das classes `PriorityStrategy` e `NotificationFactory` da Semana 4. A migração para JPA altera apenas **de onde vêm e para onde vão** os dados.

Se você mantiver o `System.out.println` nas camadas, mantenha-os: eles ajudarão a comparar o log da sua aplicação com o SQL do Hibernate.

## 9. Passo 7 (Ouro): sobreviver à reinicialização

Até aqui, `jdbc:h2:mem:` mantém os dados apenas enquanto a aplicação está rodando. Para persistir em disco, altere a URL:

```properties
spring.datasource.url=jdbc:h2:file:./data/tarefasdb
```

1. Crie três tarefas.
2. **Pare** a aplicação.
3. Inicie-a novamente.
4. Execute `GET /tasks`.

**Resultado esperado:** as três tarefas continuam lá. Sua missão principal foi cumprida.

> Adicione a pasta `data/` ao `.gitignore` para não versionar arquivos do banco.

## 11. Solução de problemas frequentes

| Sintoma | Provável causa | Ação |
|---|---|---|
| `No default constructor for entity` | Falta `@NoArgsConstructor` | Adicione a anotação na entidade |
| `Not a managed type` ou `Unknown entity` | Faltou `@Entity`, ou o pacote da entidade está fora do pacote principal | Confira as anotações e a estrutura de pacotes |
| Erro com `javax.persistence` | Import incorreto | Troque para `jakarta.persistence` |
| `id` sempre nulo após `save` | Uso do objeto original em vez do retornado | Use o valor devolvido por `save()` |
| Tabela não é criada | `ddl-auto` ausente ou incorreto | Verifique `spring.jpa.hibernate.ddl-auto=update` |
| `Table "TAREFAS" not found` no console H2 | URL do console diferente da URL do datasource | Use exatamente a mesma URL |
| Dados sumiram ao reiniciar | URL em modo `mem:` | Use `jdbc:h2:file:` |
